# Update — 2026-10-11

Commit: `6c885db` ("Hyper revamp…"). This update is an accessibility and
visual-design pass over the macOS host app: contrast, a second board theme,
discoverability of tile actions, destructive-action safety, Reduce Motion, and
VoiceOver. No data-model changes (no SwiftData migration needed).

Rules that came out of this work are in `CLAUDE.md`; architecture is in
`Jeopardy/PROJECT.md`. This file is the *record of what changed and why*.

---

## 1. Summary

| # | Change | Why |
|---|---|---|
| 1 | Contrast fixes with measured color tokens | Many text/icon colors failed WCAG/APCA |
| 2 | **Broadcast** board theme (dark backdrop) | Weaker Hermann grid illusion than Parchment in Comfortable layout |
| 3 | Hover "⋯" menu + VoiceOver actions on tiles | Edit/Delete/Reactivate only existed in the right-click menu |
| 4 | **Reactivate All** toolbar button | Imported/finished boards couldn't be replayed |
| 5 | Delete confirmations (clue, Final Jeopardy clue, player) | Unrecoverable actions had no confirmation |

Kept on purpose: the **Oxford Blue cards on Parchment** look (a deliberate
reference to the original Jeopardy board and Heralen's). The Parchment theme
is still the default.

## 2. Contrast (WCAG 2.x ratio + APCA Lc)

Every color below was measured before use (relative luminance + APCA 0.0.98G).
System window colors were approximated as `#FFFFFF`/`#ECECEC` (light) and
`#2B2B2B` (dark), so treat those figures as close, not exact.

### Failures found and fixed

| Element | Before (WCAG) | After (WCAG) |
|---|---|---|
| Revealed answer text, `.green` on white | 2.2 | 5.6–6.8 light / 7.9 dark (`jeopardyCorrect`) |
| Daily Double label / Final star / audio play, `.yellow` | 1.5 | 5.4–6.4 light / 10.0 dark (`jeopardyGold`) |
| Multiple People label, `.orange` | 2.2 | 5.5–6.5 light / 6.9 dark (`jeopardyAmberText`) |
| Red wager text/buttons, `.red` | 3.6 | 6.2–7.3 light / 5.1 dark (`jeopardyIncorrect`) |
| Opened tile `$` value (white 60% on translucent grey) | 1.5–1.65 | 6.6–7.1 (Parchment) / 9.5–10.1 (Broadcast) |
| Opened tile checkmark | 1.8–2.0 | same as above |
| Completed category header text | 2.5–3.0 | 6.3–7.7 (Parchment) / 9.5–11.5 (Broadcast) |
| Final Jeopardy announcement icon (indigo on indigo gradient) | 1.7–2.8 | 5.7+ (Saffron on Indigo Velvet) |
| "Show Clue" button (white on orange) | 2.2 | 8.7 (navy on Saffron) |
| Empty-state tile glyph (white on orange) | 2.2 | 6.1 (burnt orange); navy 16, purple 7.6 |

`PROJECT.md` previously claimed "all pairings pass AAA, ≥ 8.7:1". That held
only for white-on-navy and Saffron-on-darkest-navy; the claim was removed.

### Tokens added (`Theme/JeopardyColors.swift`)

- **Adaptive text/state colors** (light/dark pairs via `Color.adaptive`):
  `jeopardyCorrect`, `jeopardyIncorrect`, `jeopardyGold`, `jeopardyAmberText`,
  `jeopardyInfo`, `jeopardyGimmickCall`, `jeopardyGimmickCut`.
- **Fixed board fills:** `jeopardyOpened*`, `jeopardyCompleted*` (opaque, so
  contrast is exactly measurable — the old translucent whites over translucent
  greys weren't).
- **Announcement:** `jeopardyFinalDeep`, `jeopardyDailyDoubleIcon`,
  `jeopardyMultiplePeopleIcon`; backgrounds are now opaque palette gradients
  instead of a translucent blue/indigo that depended on the window appearance.
- **Empty-state tints:** `jeopardyTileNavy/Purple/Burnt`.
- **Broadcast theme:** `jeopardyBroadcast*` (see §3).

No raw `.green/.red/.yellow/.orange/.mint/.blue/.purple/.indigo` literals
remain in `Views/` or `Models/`.

### Completed headers no longer rely on color alone
Header text used to be dimmed to signal "done". It's now full-opacity white
with a small checkmark (WCAG 1.4.1).

## 3. Board themes and the Hermann grid

**Problem.** Navy cards on a light Parchment backdrop (14.7:1) is the textbook
Hermann-grid trigger; the illusion scales with the block/street luminance gap.
Tight layout (3pt gaps) removes it; Comfortable still showed some.

**Solution — `Models/BoardTheme.swift`** (persisted with
`@AppStorage("boardTheme")`):

- **Parchment** (default): unchanged look.
- **Broadcast**: backdrop `#000C1D`, ~1.2:1 against the cards. A 1pt outline
  (`#3B6EA5`, 3.7:1 vs backdrop) carries each card's boundary (WCAG 1.4.11).
  Opened tiles recede into the dark (`#0E2038`→`#0B1B30`, text `#B8C7DB`)
  instead of turning into bright grey blocks. Completed header is dark slate
  with white text.

The theme owns everything that varies with it: backdrop, text on the backdrop,
outline, opened fill/text/edge, completed fill. Views ask the theme rather than
branching.

**Toolbar:** the old "Board Layout" menu became **Board Appearance**, holding
two inline pickers (Layout and Theme). They are independent.

**Not verified:** whether Broadcast actually removes the illusion for someone
who sees it strongly. Contrast/gap math supports it; a human A/B check is the
real test.

## 4. Tile actions: discoverability

`ClueCardView` is now purely visual. New `Views/ClueCard/ClueTileView.swift`
wraps it and owns interaction. The same action list (`actionButtons`) feeds:

1. the right-click context menu (unchanged behavior),
2. a **"⋯" button that fades in on hover** (new),
3. **VoiceOver custom actions** (new): Edit Clue, Reactivate Clue, Delete Clue.

**Design note — why the "⋯" is a sibling of the link, not inside it:** a button
inside the `NavigationLink` label would let a click also navigate and fire the
link's `simultaneousGesture`, which sets `activeClue`/`selectedPoints`. Placed
beside the link in a `ZStack`, it's invisible *and inert* (`allowsHitTesting`)
until hover, so its corner never swallows clicks meant for the tile.

Reactivate Clue is disabled when the clue has nothing to reset.

## 5. Reactivate All

- Toolbar button "Reactivate All" with a confirmation dialog that states how
  many clues will reset and that **players/scores are unchanged**.
- Disabled (with an explanatory tooltip) when nothing has been played.
- Implemented via new `Clue.reactivate()`: resets `isOpened`,
  `eliminatedChoiceIndices`, **and `fiftyFiftyUsed`**. These are exactly the
  playthrough fields `BoardStorage` exports/imports, so an imported finished
  board can be replayed.
- Side fix: the single-clue Reactivate previously did **not** reset
  `fiftyFiftyUsed`; both now share `Clue.reactivate()`.
- Applies to Final Jeopardy clue too.

If a new playthrough field is ever added to `Clue`, add it to `reactivate()`.

## 6. Destructive-action safety (Nielsen #5)

New confirmation dialogs:

- **Delete Clue** — states it also deletes attached media. Deleting a clue's
  managed video file is intentional; the dialog just says so.
- **Remove Final Jeopardy clue** — same wording.
- **Remove Player** — warns that score and wager are lost.

Already confirmed before: Reset Board, board import, reset scores, reset final
wagers.

## 7. Final Jeopardy footer

**Cause:** `FinalJeopardySectionView` had a `Divider()` as the first child, and
`.padding(.vertical, 8)` applied *outside* it, leaving 8pt of bare window color
above a stray line.

**Fix:** removed the divider and top outer padding; the footer is a flush
window-colored region (Gestalt common region), so the color change is the
separator. Confirmed in a rendered check. Under Broadcast the footer is a light
strip below a dark board — a clean seam, but two different regions.

---

## 8. Reduce Motion

New `Theme/Motion.swift`: `withMotionPreference(reduceMotion:…)` and
`.slideAndFade(edge:reduceMotion:)`.

With the system setting on:
- answer reveal slide-up → fade; springs → instant,
- announcement → clue transition → instant,
- empty-state tile hover grow removed (outline/shadow change remains),
- image-lightbox zoom reset → instant,
- clear/seed board list animations → instant.

Fades are kept; layout and behavior never change. User-driven pinch/pan zoom is
direct manipulation and left as is.

## 9. VoiceOver

Labels added to: player bar add/reset buttons; player name field; score
(label + value); "−"/"+" buttons ("Add 400 dollars to Sam"); Final Jeopardy
wager field; category rename/info icons; category header (value "Completed");
image/video lightbox close buttons; clue image button; audio play/pause/stop/
volume; media remove/attached; remove-option buttons; editor help toggle;
Final Jeopardy remove; gimmick badge (name + state). Decorative icons are
hidden from VoiceOver.

Board tiles are one element: label "400 dollars, History", value
"Opened"/"Not opened", hint "Opens the clue".

## 10. Bugs found by rendering (not by contrast math)

Because screen capture was declined, visuals were checked by compiling the real
view files into a throwaway harness and rendering with `ImageRenderer`.
It caught:

1. **Shadow on text** — the tile's drop shadow was on the whole view, smearing
   the "$200" text (invisible on navy, muddy on light opened tiles). Shadow and
   fill now sit on the background shape only (tiles and headers).
2. **Daily Double "2"** — the glyph's glow showed through the knocked-out
   numeral, turning it murky grey. Glow now sits behind the icon at low opacity.
3. **Multiple choice greyed out after reveal** — `.disabled(showAnswer ||
   isEliminated)` made SwiftUI dim every row, including the correct one. Now
   only eliminated rows are disabled (`guard !showAnswer` already blocks taps).

## 13. Known gaps / next candidates

1. Keyboard-only users can't reach the hover "⋯" menu (show it on focus).
2. Broadcast opened-tile outline is 2.6:1 (deliberately dim; state is also
   carried by the check and struck-through text).
3. Dark-mode red is Lc 45 — fine for incidental text, low for body text.
4. Editor text fields rely on placeholder labels; broader VoiceOver review
   of the editor is still open.
5. A third density between Tight and Comfortable (6–8pt gaps) was suggested
   but not built.
6. Housekeeping from earlier notes: some file headers are duplicated and a few
   comments reference renamed files (`ClueFormView`, `ClueCard.swift`).
